# Nod 中文显示适配

在 Steam build 1472805 窗口模式进入主菜单后，对游戏进程作只读检查。Ghidra 12.1.4 按 0x401000 导入观察到的原生代码段。磁盘和进程代码字节不同，不以磁盘静态搜索不到引用推断运行时不存在相应函数。

| 运行时地址 | Ghidra 验证 |
| --- | --- |
| 0x4ca2f0 | 开启 NFD 资源，读取 0x1834 字节的固定头部，再读取宽度×高度的字形灰度位图 |
| 0x4ca3f0 | 按单字节索引累加整串宽度 |
| 0x4ca430 | 按单字节索引返回单字宽度 |
| 0x4ca450 | 选择绘制使用的字体对象 |
| 0x4ca470 / 0x4ca720 | 从字体对象索引字形，分别写入 16 位和 32 位目标位图 |
| 0x4d5c80 | 复制文本行至本地对象并调用整串测宽 |
| 0x4d5d30 | 在特定控件模式下逐字节测宽、寻找断点并提交行，可能切断 UTF-8 |
| 0x4d4f30 / 0x4d81f0 | 读取已排版的行，根据目标图像格式选择 16 位和 32 位绘制 |

以上地址与已知 Steam EXE SHA-256 对应，测试版适配器已经构建并同步到本机 Steam 安装目录。运行时分析副本保存在 Analysis，不提交。

`build_chinese_glyphs.py` 从正式正文和本机 Noto Sans SC 生成灰度字形表。`verify_glyph_table.py` 独立校验三种字号的全部 2,543 个非 ASCII 字形及格式。`nod_layout.hpp` 校验 UTF-8 并按完整字符测宽断行，已用混合标点、长短音节与坏序列进行独立编译测试。`adapter.cpp` 使用本机 WinMM 转发和 MinHook 接入这三条路径。它检查运行时入口字节，中文通过临时字形视图调用原绘制函数。英文和原版单字节字符串走原函数。启动实测通过，小字号字形已改用 650 字重及 NFD 的底朝上行序。
